## Domain contracts

This document defines the smallest shared contract for the first editorial
inventory slice. It is consumed by the future Go application layer, SQLite
adapter, and Next.js API client. It does not define persistence migrations,
HTTP routes, UI components, seed data, or a status vocabulary.

### General rules

- An omitted optional field remains absent. Consumers MUST NOT replace it with
  an invented value, status, date, owner, metric, or relationship.
- Collections are empty when no related records exist; they MUST NOT contain
  `null` items.
- Text fields are trimmed before validation. Required text MUST be non-empty
  after trimming.
- Every related record belongs to exactly one project. Cross-project
  associations MUST be rejected.
- These contracts contain curated metadata only. Source contents, credentials,
  environment files, transcripts, private URLs, and uncurated generated
  artifacts are not valid values for any field.

### Project

| Field | Required | Contract |
| --- | --- | --- |
| `id` | Yes at persistence boundary | Stable local identifier generated by the application; callers MUST NOT invent it. |
| `name` | Yes | Non-empty curated display name. |
| `description` | No | Curated user-facing description; omitted when unavailable. |
| `technologies` | No | Zero or more non-empty curated technology labels. The list has no implied taxonomy. |
| `agentic_platform` | No | Curated name of the agentic platform used by the project; omitted when not recorded. |
| `links` | No | Zero or more `PublicLink` records belonging to this project; at most one GitHub and one Trello link. |
| `media` | No | Zero or more `MediaAsset` records belonging to this project. |
| `milestones` | No | Zero or more `Milestone` records belonging to this project. |

The contract intentionally does not add owner, category, lifecycle state,
metrics, automatic timestamps, or repository paths. A future change may define
one of those fields explicitly.

### PublicLink

`PublicLink` is an inert display record, not an integration.

| Field | Required | Contract |
| --- | --- | --- |
| `kind` | Yes | Exactly `github` or `trello`. |
| `url` | Yes | Absolute HTTPS URL with a non-empty path. Host MUST be `github.com` or `www.github.com` for `github`, and `trello.com` or `www.trello.com` for `trello`. |
| `label` | No | Curated display label; omitted when unavailable. |

URL validation MUST reject non-HTTPS schemes, userinfo, localhost, loopback or
private/reserved hosts, unsupported hosts, and malformed URLs. Validation MUST
not fetch, resolve, import, synchronize, or otherwise contact the destination.
The original validated URL is displayed; the application MUST NOT manufacture a
replacement URL or expose private query values. These links do not authorize
access to repository code, Trello cards, activity, or any remote content.

### MediaAsset

Each asset represents one curated presentation role and is associated with one
project.

| Field | Required | Contract |
| --- | --- | --- |
| `id` | Yes at persistence boundary | Stable local identifier generated by the application. |
| `role` | Yes | Exactly `thumbnail`, `original`, `screenshot`, or `video`. |
| `source` | Yes | One managed local relative path for local media, or one validated public HTTPS URL for an external video. |
| `curated` | Yes | Must be explicitly `true`; the API MUST reject media without an explicit curation decision. |
| `original_media_id` | No | Only allowed on a `thumbnail`; references an `original` belonging to the same project. |
| `alt_text` | No | Curated accessible description for visual media; omitted when unavailable. |
| `caption` | No | Curated display caption; omitted when unavailable. |

Managed paths MUST use an approved presentation-media extension and MUST NOT
contain hidden files, source/configuration files, transcripts, or generated
artifact directories. `thumbnail` is a compact preview and MAY point to its full-size `original` via
`original_media_id`. `original` is the enlargement target and does not point
back to its thumbnail. `screenshot` is a curated visual capture and is not a
thumbnail unless represented by a separate `thumbnail` asset. `video` is either
a managed local video file or a validated public HTTPS video URL; this task does
not define a provider or a remote import. A media source MUST NOT be an
arbitrary repository path, source file, credential, transcript, or uncurated
generated artifact.

An association is valid only when the referenced original exists, has role
`original`, and belongs to the same project. Missing references, self-links,
cycles, and references to another project MUST be rejected.

### Milestone

| Field | Required | Contract |
| --- | --- | --- |
| `id` | Yes at persistence boundary | Stable local identifier generated by the application. |
| `project_id` | Yes | Existing project identifier. |
| `date` | Yes | Calendar date in `YYYY-MM-DD` format; no timezone or invented timestamp. |
| `title` | Yes | Non-empty curated title. |
| `description` | Yes | Non-empty curated description. |
| `media_ids` | No | Zero or more IDs of curated media belonging to the same project. |

Milestones are user-authored records and are shown in ascending calendar-date
order. Equal dates have no implied precedence. Creating or editing a milestone
MUST NOT create an automatic Git or Trello event.

### Validation examples

Implementations MUST cover these cases at their owning validation seam:

- accept a project with only `name`;
- reject a project with a blank `name`;
- accept omitted optional fields without filling them in;
- accept one valid HTTPS GitHub URL and one valid HTTPS Trello URL;
- reject HTTP, unsupported-host, userinfo, localhost, and private-host URLs;
- accept a thumbnail linked to an original in the same project;
- reject a thumbnail linked to a screenshot, a missing original, or another
  project;
- accept a milestone with `date`, `title`, and `description`;
- reject a milestone missing any of those three required fields;
- reject media or milestone relationships that point to another project.

No implementation code or runtime persistence is introduced by this contract
task; these examples are test obligations for the API/domain task.
